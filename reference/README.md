# reference/ : provenance snapshots

Everything here is a VERBATIM copy of a file of the reference machine (the machine that produced the results this
repository reproduces), taken on 2026-10-12, or a table generated from its runs. Nothing here is imported or
executed by the repository, and these files are the only place where the reference machine's absolute paths and
the pre-rename names appear. They are kept so that every argv, name and number in the repository can be traced to
where it came from. Do not edit them; `SHA256SUMS` lists the checksums of the verbatim copies
(`cd reference && sha256sum -c SHA256SUMS`).

**Names.** The method is called DVD in this repository. The research code called it SVG, so the snapshots say
`--svg-weight`, `svg_term.py`, `dsrl-na-svg1.0_...`, `<step>_svg.pt` where the repository says `--dvd-weight`,
`dvd_term.py`, `dsrl-na-dvd1.0_...`, `<step>_dvd.pt`. `rl/online_rl_mimicgen/legacy.py` is the one module that
maps old names to new ones.

## Reading the launchers

They cannot run anywhere else (absolute paths, the reference machine's queues and eval daemons). What they define:

- the argv of every cell, which `configs/` reproduces token for token. One trap: `launch_dicerl*.sh` builds
  `NSTEP=(--nstep 1)` for `ARM=q` and then `unset`s `NSTEP` (line 98) before using it, so no Q run was launched with
  that flag. 1 is the default, so the configuration is the same.
- the run names and wandb groups, kept by `configs/` (with `svg` -> `dvd`). The bare group `<task>_dicerl_dvd` is
  TD + distill on square_d0 and TD only on the other tasks.
- per-task assets: prior, world model (DICE-RL on hammer_cleanup_d1 loads the base model, everything else the
  continuation), V directory (`_pv4` for DICE-RL; `_pv4` or `_pv4_seg` for DSRL), RoboMeter spool. `configs/tasks.sh`
  is the same table with the roots of `scripts/env.sh`.
- their header comments record why each arm exists and the analysis notes of the distill A/B.

## critic_ood_study/ (not ported)

The study behind "gamma^8 V(f(s, a)) ranks nearby out-of-distribution actions better than Q(s, a)": at
decision-critical states of the seed-44 DSRL Q run and DSRL + DVD run (checkpoints 175k / 400k / 600k, four tasks),
the executed action chunk is shifted along one action axis, each candidate is rolled out 16 times from an exact
simulator snapshot with common random numbers, and each critic's ranking of the candidates is scored against the
true outcomes. Result: V(f) is ahead in all 12 task x checkpoint cells (pooled accuracy 0.61 against 0.51).

- `q_on_ood/qood.py` (core: snapshots, perturbations, critic scores, Monte Carlo ground truth), `round2.py`,
  `round3.py`, `late.py` (stages per checkpoint and task), `analyze_step.py` (aggregation into
  `figs_steps/results_<tag>.pkl`).
- `1008_weeklymeeting_ablationstudy/make_figures.py` (figures and `numbers.csv` from those pickles), its
  `numbers.csv` (the expected output) and `README.md` (setup, definitions and every number of the study).

These scripts still use the research tree's names and layout: they import `svg_term`, `dino_svg` and
`online_rl_mimicgen.baselines.dsrl_dino` from the research tree, read `<step>_svg.pt` sidecars, hard-code the
reference machine's run directories, and find the two runs by their `dsrl-na-q_*` / `dsrl-na-svg1.0_*` names. To
run them against this repository they need the renames of `legacy.py`, the roots of `scripts/env.sh` and the
seed-44 checkpoints at 175k / 400k / 600k of both arms on each task. The shell wrappers that scheduled the
stages on the reference machine are not included.
